# Time base selection for STM32+FreeRTOS project

## 1. Why the Time Base Must Be Changed ?
- FreeRTOS uses the ARM Cortex-M processor's internal `SysTick` timer as its default time base.
- The FreeRTOS time base supports timing functions such as:
	- Task delays.
	- Scheduling tasks at defined intervals.
	- Running the scheduler at predefined intervals.
- In our project we are using the Hardware Abstraction Layer(HAL) to communicate to the various peripherals UART, SPI, ADC etc.
- The STM32CubeIDE Project's HAL also uses `SysTick` by default for delays and timeout functions.
- Using `SysTick` for both `FreeRTOS` and `HAL` creates a time-base conflict.
- So we will dedicate the `SysTick` to FreeRTOS and use a MCU's timer peripheral for the STM32Cube HAL i.e. TIM6.

## 2. Select the HAL Time Base
1. Open the .ioc file using the `STM32CubeMX`.
2. Go to **System Core > SYS**.
3. Locate **Time base source**. Use the horizontal scrollbar if the setting is hidden.
4. Change the STM32Cube HAL time base from `SysTick` to `TIM6`.

## 3. Configure the NVIC Priority Group
1. Open **NVIC** in the device configuration tool.
2. Set the priority group to **4 bits for preemption priority and 0 bits for sub-priority**.
- ARM Cortex-M hardware priority uses 4 bits in this project.
- Using all 4 bits for preemption priority avoids dividing the priority bits with sub-priority.

## 4. Generate and Build
- Generate the project code after changing the time base and priority group.
- The generated source includes `stm32f4xx_hal_timebase_timer.c`.
- This file initializes `TIM6` to provide the HAL time base at one-millisecond intervals.
- Build the project again; it should build successfully.

## Result
- The FreeRTOS kernel can use `SysTick` for RTOS timing while the STM32Cube HAL uses `TIM6`.
- The project is now ready for the next stage: learning about FreeRTOS tasks and creating the first task in `main.c`.
