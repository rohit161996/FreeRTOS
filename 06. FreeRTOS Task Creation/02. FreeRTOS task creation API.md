# FreeRTOS task creation API

## 1. `xTaskCreate()`
- `xTaskCreate()` creates a FreeRTOS task using **dynamic memory allocation**.
- A successfully created task is added to the kernel's ready list (ready queue).
- The API returns a `BaseType_t` status value that the application can check to confirm whether task creation succeeded.
- Reference: freertos.org → Kernel → API Reference → Tasks → Task Creation → `xTaskCreate()`.

```c
BaseType_t xTaskCreate(
	 TaskFunction_t pvTaskCode,           // Address of the associated task handler
	 const char * const pcName,           // A descriptive name to identify the task
	 configSTACK_DEPTH_TYPE usStackDepth, // Amount of stack memory allocated to this task (in words, not bytes)
	 void *pvParameters,                  // Pointer to the data which needs to be passed to the task handler once it gets scheduled
	 UBaseType_t uxPriority,              // Task priority value
	 TaskHandle_t *pxCreatedTask          // Used to save the task handle (an address of the task created)
);
```

## 2. API Parameters
1. `pvTaskCode`
	- Function pointer to the task handler function.
	- The scheduler runs this function when it dispatches the task onto the CPU.
2. `pcName`
	- Descriptive name used to identify the task.
	- Purely for the user/developer's convenience (identification); not used by the kernel for scheduling.
3. `usStackDepth`
	- Number of **words**, not bytes, to allocate for the task's private stack.
	- Each task gets its own private stack, sized by this parameter.
	- On a 32-bit ARM Cortex-M processor, a stack depth of `400` represents `400 * 4 = 1600` bytes.
	- The parameter's type is `configSTACK_DEPTH_TYPE` (see Section 4).
4. `pvParameters`
	- Pointer to data passed to the task handler when it runs on the CPU.
	- Lets the application hand information to the task at the time it is scheduled.
5. `uxPriority`
	- Priority assigned to the task (type `UBaseType_t`).
	- When two or more tasks exist, priority decides which one runs first on the CPU.
	- Priority can be set high or low; covered in more detail in a later lecture.
6. `pxCreatedTask`
	- Optional output pointer where FreeRTOS stores the created task's handle.
	- A task handle is just an address/number that identifies the created task.
	- Once you have the handle, you can later suspend, block, or delete that task using it.

## 3. Stack Depth and Word Size
- A **word** is the maximum size of data the processor can access (load/store) in a single clock cycle using a single instruction.
- Processor design offers native support for word-sized operations — matching register width and bus width.
- Word size depends on processor architecture: it could be 8-bit, 16-bit, 32-bit, or more.
  - ARM Cortex-Mx microcontrollers: 32-bit word size.
- The stack depth parameter is expressed in words (not bytes) precisely because word size is architecture-dependent.
- Examples:
  - 16-bit-wide stack, `usStackDepth = 100` → `100 * 2 = 200` bytes allocated.
  - 32-bit-wide stack, `usStackDepth = 400` → `400 * 4 = 1600` bytes allocated.
- ARM Cortex-M processors use a 32-bit-wide stack with a **full-descending stack model**: the stack pointer (SP) starts at a higher memory address and moves toward lower addresses as data is pushed. Each push moves 32 bits of data.
- This model/width is architecture-specific — other processors may differ; consult the processor's design documentation.

## 4. `configSTACK_DEPTH_TYPE`
- `configSTACK_DEPTH_TYPE` is a macro that sets the **type** used for the stack-depth parameter in `xTaskCreate()` (and other places stack sizes appear).
- It is defined in `FreeRTOS.h`, and by default currently resolves to `uint16_t`.
- **History:** older versions of FreeRTOS didn't have this macro — stack depth was always specified using `UBaseType_t`.
  - `UBaseType_t` is defined as the most efficient natural type for the target architecture (see Section 5).
  - On an 8-bit microcontroller, that meant `UBaseType_t` effectively became `uint8_t` — capping the maximum stack depth at `255` words, which turned out to be too restrictive.
- `configSTACK_DEPTH_TYPE` was introduced to remove this restriction, decoupling the stack-depth type from `UBaseType_t`.
- If the current default (`uint16_t`) is still too restrictive for an application, it can be redefined in `FreeRTOSConfig.h` to any desired data type.

## 5. Related FreeRTOS Types
- `BaseType_t` — defined as the most efficient, natural type for the target architecture:
  - 32-bit architecture (e.g., ARM Cortex-Mx) → typedef'd to a 32-bit C type.
  - 16-bit architecture → typedef'd to a 16-bit type.
  - 8-bit architecture → typedef'd to an 8-bit type.
- `UBaseType_t` — the unsigned form of `BaseType_t`; used for task priority (`uxPriority`) and, in older FreeRTOS versions, for stack depth.
- `TaskHandle_t` — identifies a task after it has been created; obtained via `pxCreatedTask`.
- Full naming/type conventions are documented under: freertos.org → Kernel → Developer Documentation → About FreeRTOS Kernel → Coding Style.

## Key Points
- Provide a handler, name, stack depth, parameter pointer, priority, and (optionally) an output handle to `xTaskCreate()`.
- Stack depth is always measured in **words**, not bytes — multiply by the architecture's word size (in bytes) to get the actual byte allocation.
- `configSTACK_DEPTH_TYPE` (in `FreeRTOS.h`, default `uint16_t`) controls the stack-depth parameter's type, and exists specifically to avoid the old `UBaseType_t`-based 255-word ceiling on 8-bit MCUs.
- A task handle allows later task-control operations (suspend, block, delete).
- Check the `BaseType_t` return value of `xTaskCreate()` to confirm task creation succeeded.
