# FreeRTOS task creation API

## 1. `xTaskCreate()`
- `xTaskCreate()` creates a FreeRTOS task using dynamic memory allocation.
- A successfully created task is added to the kernel's ready list.
- The API returns a status value that can be checked by the application.

```c
BaseType_t xTaskCreate(
	 TaskFunction_t pvTaskCode,           // Address of the associated task handler
	 const char * const pcName,           // A descriptive name to identify the task
	 configSTACK_DEPTH_TYPE usStackDepth, // Amount of stack memory allocated to this task(memory in words not in bytes)
	 void *pvParameters,                  // Pointer to the data which needs to be passed to the task handler once it gets scheduled
	 UBaseType_t uxPriority,              // Task priority value
	 TaskHandle_t *pxCreatedTask          // Used to save the task handle(an address of the task created)
);
```

## 2. API Parameters
1. `pvTaskCode`
	- Pointer to the task handler function.
	- The scheduler runs this function when it dispatches the task.
2. `pcName`
	- Descriptive name used to identify the task.
	- The name is provided for user convenience.
3. `usStackDepth`
	- Number of words to allocate for the task's private stack, not the number of bytes.
	- On a 32-bit ARM Cortex-M processor, a stack depth of `400` represents `400 * 4 = 1600` bytes.
4. `pvParameters`
	- Pointer to data passed to the task handler when it runs.
	- The application can use it to provide information required by the task.
5. `uxPriority`
	- Priority assigned to the task.
	- The scheduler uses task priorities when deciding which task should run.
6. `pxCreatedTask`
	- Pointer where FreeRTOS stores the created task's handle.
	- The handle can later be used to suspend, block, or delete the task.

## 3. Stack Depth and Word Size
- A word is the natural data width used by the processor for operations such as loading, storing, pushing, and popping data.

- Word is a max size of the data which can be accessed(load/store) by the processor in a single clock cycle using a single instruction.

- Processor design also offers native support (register width, bus width) to load/store word sized data.

- Word size could be 8bit/16bit/32bit or more, depending upon the processor design. For ARM Cortex Mx based microcontrollers, word size is 32 bits.

- The stack depth parameter is measured in words because the word size depends on the processor architecture.

- Examples:
  - A 16-bit stack with a depth of `100` allocates `100 * 2 = 200` bytes.
  - A 32-bit stack with a depth of `400` allocates `400 * 4 = 1600` bytes.

- ARM Cortex-M processors use a 32-bit stack and a `full-descending stack model`: the stack pointer moves toward lower addresses as data is pushed.

- Other processor architectures may use 8-bit or 16-bit words, so their byte calculation is different.

## 4. `configSTACK_DEPTH_TYPE`
- `configSTACK_DEPTH_TYPE` specifies the type used for the stack-depth parameter in `xTaskCreate()` and other stack-size contexts.
- Older FreeRTOS versions used `uint8_t` for stack sizes.
- That type could be too restrictive on small architectures, such as 8-bit microcontrollers, where it could limit the maximum value to `255`.
- The configurable type removes that restriction and can be redefined in `FreeRTOSConfig.h` when the application requires a different type.

## 5. Related FreeRTOS Types
- `BaseType_t` is defined as the most efficient natural type for the target architecture.
- On a 32-bit processor, it is based on a 32-bit C data type; on 16-bit and 8-bit processors, it is based on the corresponding native width.
- `UBaseType_t` is the unsigned form used by several FreeRTOS APIs, including task priority values.
- `TaskHandle_t` identifies a task after it has been created.

## Key Points
- Provide a handler, name, stack depth, parameter pointer, priority, and optional output handle to `xTaskCreate()`.
- Stack depth is measured in words, not bytes.
- A task handle allows later task-control operations.
- Check the `BaseType_t` return value to determine whether task creation succeeded.
