## Question 1:
*If a FreeRTOS Task is created with 512 bytes of the stack, how many bytes in the heap region will be consumed?*

**A.** - 512 bytes

**B.** - (512 * 4) + sizeof(TCB)

**C.** - 512 + sizeof(TCB)

## Answer
- If a FreeRTOS task is created with **512 bytes** of the stack, the argument which should be passed in the **xTaskCreate()** should be **128** since the argument in the xTaskCreate() for stack depth is taken in **words** not bytes. [512 Bytes]

- 1 word in STM32 is 32 bits i.e. 4 bytes, 1 word = 4 bytes. [512 Bytes]

- Along with the 512 bytes the `heap_4.c` adds a 8 bytes header(with the usual 8 bytes alignment), while calling the `pvPortMalloc()`.

- Now, xTaskCreate() also creates a TCB memory block, using a second `pvPortMalloc()` call.

- TCB's length is not fixed, it depends on the macro `configMAX_TASK_NAME_LEN`.

Answer = `512 Bytes + sizeof(TCB_t);`

## Question 5:
*Is it possible to create a Task in FreeRTOS by static allocation methods?*

**A.** Yes

**B.** No, FreeRTOS only supports dynamic memory allocation methods.

## Answer

Yes — FreeRTOS supports static task creation via `xTaskCreateStatic()`, as an alternative to the dynamic `xTaskCreate()` we've been using.

```c
// FreeRTOSConfig.h
#define configSUPPORT_STATIC_ALLOCATION    1
```

You can have `configSUPPORT_STATIC_ALLOCATION` and `configSUPPORT_DYNAMIC_ALLOCATION` both set to 1 at the same time — they aren't mutually exclusive; you choose per task/object which one to use.

The key difference: with `xTaskCreate()`, the kernel calls `pvPortMalloc()` internally to get memory for the TCB and the stack, out of the heap. With `xTaskCreateStatic()`, you supply that memory yourself — as statically (or globally) allocated buffers — so nothing comes out of the FreeRTOS heap for that task at all.

## Question 6:
*Where will be the location of the stack memory of the task, if it is created statically?*

**A.** Stack space of the RAM.

**B.** Heap space of the RAM.

**C.** Global space of the RAM.

## Answer
C. Global space of the RAM.
- If the task is created statically both the TCB and the stack of the Task will live in the global space of the RAM, i.e. out of the Stack and the Heap Area.

## Question 7:
Where will be the location of the stack memory of the task, if it is created dynamically?

A. **Stack space of the RAM**.

B. **Heap space of the RAM**.

C. **Global space of the RAM**.

## Answer
B. Heap space of the RAM.

When you use `xTaskCreate()`, the task's private stack is one of the two `pvPortMalloc()` allocations pulled from the FreeRTOS heap (the `configTOTAL_HEAP_SIZE`-sized array managed by `heap_4.c`) — the same heap you were computing byte-consumption for a few questions ago. It is not placed on the CPU's own stack (that's reserved for `main()` and interrupt/exception handling via MSP before the scheduler starts, and after that mostly unused by application tasks), and it's not in global/static space either — that's where `xTaskCreateStatic()`'s buffers would live instead, not dynamically-created ones.
